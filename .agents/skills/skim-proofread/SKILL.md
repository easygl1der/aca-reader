# Skim Proofread Skill

## 功能
通过 Skim 逐个跳转到问题位置，让用户视觉确认问题后再执行修复。

## 触发条件
- 用户要求"校验"、"proofread"、跳转检查
- 需要用户确认后才修复的场景

## 核心工作流

### 步骤 1: 收集问题列表
从 proof-reading-experts 团队或自检获取问题清单，包含：
- 行号
- 问题描述
- 严重程度

### 步骤 2: 逐个跳转确认
对每个问题执行：
```bash
/Applications/Skim.app/Contents/SharedSupport/displayline -r -g <行号> "<PDF>" "<TeX>"
```

跳转后：
1. 描述问题是什么
2. 说明为什么是问题（或为什么不是问题）
3. 等待5秒：`sleep 5`
4. 进入下一个跳转

### 步骤 3: 用户确认
展示问题汇总表：
```
| # | 行 | 问题 | 操作 |
|---|-----|------|------|
| 1 | 202 | 孤立等式残留 | 删除? |
```

等待用户指令：
- 哪些需要修复
- 哪些不是问题

### 步骤 4: 执行修复
根据用户确认，只修复用户同意的问题。

## 经验教训（2026-03-31）

### NOT 问题（用户确认）
- **行202 孤立等式**：Theorem 后的推导等式是正常的数学表述，不是残留
- **行44 脚注在 Theorem 内**：技术上可行，不算错误

### 是问题（需修复）
- **行150 `\ref`→`\cref`**：应统一使用 \cref
- **行308 `\ref`→`\cref`**：应统一使用 \cref

## 注意事项
- 跳转后必须等待5秒让用户看清
- 必须等用户确认后才修复
- 不要假设 AI 认为是问题就必须修复
