# 经验教训汇总

## 格式规范

- **LaTeX 禁止 Markdown**：禁止使用 `-`、`1.`、`**`、`*`、``` 等 Markdown 语法
- **Label 格式**：`\label{def:名称}`，引用用 `\cref{名称}`

## 阅读技巧

- **先读目录**：读取任何 PDF 书籍时，必须先读 Table of Contents 确认章节结构
- **对照原文**：直接读取原文对照，避免凭记忆写笔记

## 技术细节

- **R 绘图**：默认不支持中文，所有 R 图表必须使用英文标签
- **LaTeX 图片**：[H] 强制固定图片位置（需 float 宏包）
- **论文链接**：1998年以前的论文通常没有 arXiv 版本，应使用 DOI

## 项目结构

- **Memory 截断**：MEMORY.md 超过 200 行会被截断，重要内容写入 CLAUDE.md
- **Claude.md 精简**：详细规范拆分到 docs/ 目录，CLAUDE.md 保持简洁

## 2026-03-19

- **不要编造引理**：笔记中的 Lemma 2.1, 2.2, 2.3 是我编造的，论文中不存在。必须对照原文确认每个定理/引理的正确内容
- **参考文献显示问题**：references.bib 中有 30 篇，但 PDF 只显示被 \cite{} 引用的 23 篇。LaTeX 不会显示未被引用的文献
- **git commit 失败**：pre-commit hook 检查文件大小，同时 webpage/app submodule 有修改会导致无法提交
- **Gemini 标注**：用 Gemini 生成的回答，必须在附近用 footnote 标注 "Generated by Gemini"

## 2026-03-30

- **用户验证 vs 文献查询**：当用户说"你看一下这个计算对不对"时，应先在用户的笔记文件中查找定义/公式来验证，而不是去文献库找其他PDF
- **最小化修改原则**：修正公式错误时，先确认正确的公式形式，只修改用户指出的那一行，避免破坏后续的计算例子
- **编辑后验证**：修改 LaTeX 公式后必须编译检查，确保没有引入新的错误

## 2026-03-30（续）

- **公式引用规范**：引用公式必须用 `\cref{eq:label}` 而不是 `式 (★)` 或 `\tag{}`。每个公式在定义时用 `\label{eq:名称}` 标记，引用时用 `\cref{eq:名称}`
- **禁止使用 Markdown 符号**：LaTeX 文件中禁止使用 `**加粗**`、`- 列表项` 等 Markdown 符号，必须用 `\textbf{}` 和 `\begin{itemize}\item ...\end{itemize}`
